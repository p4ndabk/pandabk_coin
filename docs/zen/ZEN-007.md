# ZEN-007: Backup mnemônico (BIP39) e derivação de chave (SLIP-0010)

`final` · `interoperabilidade`

## Resumo

Define como uma frase de 12 palavras recupera a chave privada de uma
wallet Zhu — usando os padrões abertos BIP39 (frase mnemônica) e SLIP-0010
(derivação de chave em curvas não-secp256k1, aqui NIST P-256). Qualquer
implementação (nesta linguagem ou outra) que siga estas duas specs produz a
mesma chave a partir da mesma frase.

## Motivação

Perder a chave privada é perder os fundos para sempre — não existe "esqueci
a senha" em blockchain. Um formato de backup caseiro prenderia o usuário a
este binário específico: se o projeto Zhu desaparecesse, a frase de
recuperação seria inútil. Usar BIP39 (a mesma wordlist e checksum que
carteiras Bitcoin usam) e SLIP-0010 (a extensão da Trezor para derivação
em curvas fora do secp256k1) significa que as mesmas 12 palavras recuperam
a carteira com qualquer biblioteca que implemente essas specs — por
exemplo, `mnemonic` em Python + qualquer implementação de SLIP-0010 —, sem
depender deste código continuar existindo.

## Especificação

### Geração da frase (BIP39)

- **128 bits de entropia** (`crypto/rand`, nunca `math/rand` — entropia
  previsível é uma chave adivinhável) + **4 bits de checksum**
  (`SHA-256(entropia)` truncado aos primeiros `entropia_bits / 32` bits) =
  132 bits, divididos em **12 grupos de 11 bits**, cada grupo indexando uma
  palavra da wordlist.
- **Wordlist**: a lista inglesa oficial do BIP39, 2048 palavras.
- O resultado são as **12 palavras** mostradas ao usuário **uma única vez**
  na criação (`NewWithMnemonic`) — não fica salva em texto plano junto da
  wallet.

### Derivação da chave-mestra (SLIP-0010, curva NIST P-256)

A partir da frase (convertida em seed pelo processo padrão BIP39 —
PBKDF2-HMAC-SHA512 da mnemônica + passphrase opcional, 2048 iterações), a
chave-mestra é derivada conforme **SLIP-0010** especificamente para
`nist256p1` (não secp256k1 — a wallet Zhu usa ECDSA P-256 em todo o resto
do sistema, ZEN-001, então a derivação segue a mesma curva por
consistência):

```
seed              = PBKDF2-HMAC-SHA512(mnemonic, "mnemonic" + passphrase, 2048 iter, 64 bytes)
I                 = HMAC-SHA512(key="Nist256p1 seed", data=seed)
masterPrivateKey  = I[:32]   // rejeitar/ajustar se ≥ ordem da curva, conforme SLIP-0010
masterChainCode   = I[32:]
```

A chave privada resultante é usada diretamente como a chave ECDSA P-256 da
wallet (sem derivação hierárquica adicional — HD wallets multi-endereço
são explicitamente fora de escopo, ver Compatibilidade).

### Restauração

`Restore(mnemonic, path)` recalcula a chave-mestra a partir da frase e
grava um novo `wallet.json` no `path` indicado, com as mesmas regras de
`New` (falha com `O_EXCL` se o arquivo já existe — nunca sobrescreve uma
wallet existente).

### Vetores de teste

Uma implementação conforme deve bater com os vetores oficiais usados por
este projeto para validar a derivação:

- **BIP39**: vetores de teste oficiais da Trezor.
- **SLIP-0010**: vetor de teste 1 para `nist256p1` (curva NIST P-256) da
  especificação SLIP-0010.

## Casos de erro

- Wallets criadas **antes** deste ZEN (chave puramente aleatória, sem
  frase) continuam válidas e utilizáveis — nunca deixam de funcionar por
  não terem mnemônico. Elas simplesmente não têm um backup em frase.
- Frase mnemônica com checksum inválido (palavra errada, ordem errada) →
  erro de restauração, nunca aceitar silenciosamente uma chave errada.

## Compatibilidade

Isto é uma extensão aditiva sobre o formato de wallet existente (ZEN-001
para endereço, formato interno de `wallet.json` fora do escopo de
consenso): wallets antigas continuam válidas. Não há HD wallet
(BIP32/BIP39 multi-conta) — uma frase recupera **uma única chave/endereço**,
não uma árvore de contas; um ZEN futuro que adicionasse múltiplos
endereços por seed precisaria definir o caminho de derivação (`path`) e
seria aditivo desde que a derivação de conta única aqui descrita continue
válida como caso base.
